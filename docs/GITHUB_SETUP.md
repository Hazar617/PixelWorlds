# GitHub – препоръчителна структура и стъпки

## 1. Препоръчителна структура

Запазете съществуващата Unity папка и не местете отделно нейните основни директории. Препоръчителната структура на хранилището е:

```text
PixelWorlds/
├── README.md
├── LICENSE
├── .gitignore
├── .gitattributes
├── docs/
│   ├── MVP.md
│   ├── TESTING.md
│   ├── BUGS.md
│   ├── CONTRIBUTION.md
│   └── screenshots/
│       └── .gitkeep
└── pixelworlds/
    └── src/
        └── 2D/
            ├── Assets/
            ├── Packages/
            └── ProjectSettings/
```

Това е целева/примерна структура. Преди преместване проверете дали `pixelworlds/src/2D` действително съдържа `Assets`, `Packages` и `ProjectSettings`. Ако те са на друго място, запазете реалния Unity project root и адаптирайте схемата.

## 2. Какво да качите

1. В GitHub отворете хранилището `Hazar617/PixelWorlds`.
2. Натиснете `Add file` → `Upload files`.
3. Качете `README.md` в основната директория на хранилището.
4. Създайте папка `docs` и качете четирите Markdown файла в нея.
5. В `docs` създайте `screenshots` и качете 5–10 ясни снимки от реалната игра, ако това е изискване на вашия преподавател. Не използвайте примерни или генерирани изображения като доказателство за работеща функционалност.
6. Напишете кратко описание на промените в полето за commit.
7. Натиснете `Commit changes`.

## 3. Unity файлове

В Unity проекта обичайно трябва да се запазят `Assets`, `Packages` и `ProjectSettings`. Не качвайте временни/генерирани папки като `Library`, `Temp`, `Obj`, `Logs` и `Build` – те се създават от Unity и могат да заемат много място. Проверете съществуващия `.gitignore`, преди да го променяте; не го заменяйте сляпо.

## 4. Преди да местите файлове

- Направете копие на целия проект на компютъра.
- Проверете коя папка съдържа `Assets`, `Packages` и `ProjectSettings`.
- Отворете тази папка чрез Unity Hub и проверете дали проектът се зарежда.
- Не преименувайте и не местете Unity project root, докато Unity е отворен.
- След промяна качете файловете и проверете дали структурата в GitHub е правилна.

## 5. Препоръчителни commit съобщения

- `docs: add project documentation`
- `docs: update MVP status`
- `test: add manual test cases`
- `fix: resolve player movement issue` – използвайте само след реално отстраняване и проверка на проблема.
